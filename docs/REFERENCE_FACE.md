# Demo reference-face check and adaptive entry

The normal student flow is always the meeting room. Room type, answer window and automatic-microphone checkboxes are removed. Responses use server-owned question budgets: 12 seconds for short explanations/follow-ups, 15 for longer explanations, 20 for changed scenarios/long questions, 25 for bugs or complex changes. Students cannot override the budget through the meeting endpoint. Existing fixed-window attempts upgrade when rejoining; completed response records are unchanged.

Join requires a live camera, a detected calibrated face and two consecutive local reference matches. A last matching result alone does not unlock entry when the face leaves the frame. Microphone permission is requested at Join; the small Microphone unavailable? option permits typing. A missing camera never unlocks joining on its own; unavailable-camera exceptions require explicit human review.

The demo references are two portraits the user supplied of Adnane Essoufi, copied unchanged into public/identity. They represent one known target person, not an identity gallery or a search for unknown people. This fixed demo reference must not be represented as the enrolled identity of every real student. A future real student deployment needs individually assigned, consented references and genuine authentication, outside this local demo's scope.

@vladmandic/face-api 1.7.15 is pinned, with only tiny face detection, tiny 68-landmark alignment and face-recognition model files self-hosted. No age/gender/emotion models are loaded or invoked. Face descriptors and frames stay in memory on the laptop; no embeddings or camera pictures are uploaded, logged by the app or persisted in SQLite. Matching uses minimum Euclidean descriptor distance against the two portraits of the same person, threshold 0.6. Two consecutive candidate matches are required. Detection uses the standard 0.5 score threshold and 416-pixel input; a 0.65/320 setup failed to detect the reference and was corrected using measured detector output (reference detection score about 0.564).

This is reference-photo comparison, not official ID-document verification or proof of a live person. Lighting, glasses, aging, pose, image quality, false matches/nonmatches and printed-photo/video spoofing remain limitations. Inconclusive/unavailable comparisons require teacher review, not automated disqualification. A changed nonmatching face sustained across three actual comparison samples in a joined meeting requests human review. Teacher ID/circumstance review is required to approve an exception. Human approval is explicitly recorded; it is not relabelled as an ML-verified ID. Prototype Teacher/Student roles remain unauthenticated demo access; client status is device-reported and not tamper-proof.

Reference model loading starts during preflight to overlap avatar preparation. Initial cold model/shader loading can take time; Join remains disabled until it finishes. The supplied photo is reused unchanged for reference matching, separate from the D-ID animation's generated pixels.

Verification: actual browser/local model matched the exact supplied portrait (distance 0) and returned review-required for a different public COCO face (distance about 0.806). This is a bounded software-pipeline check, not a population accuracy estimate.
